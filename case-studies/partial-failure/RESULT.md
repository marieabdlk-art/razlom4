# Partial failure pilot — result

Дата: 2026-07-28

Статус: `NO_VALID_MUTATION`

Тип: blind single-case pilot, не статистический benchmark.

## Строгий итог

Ни один из четырёх DeltaCandidate не пережил внешнюю гильотину. Кандидат с
лучшим maximin, Uncertainty Escrow (`0.48`), имел подтверждённый C1/C4 veto.
Единственный разрешённый ремонт честно завершился `REJECT`.

Причина не в выборе rollback против forward, а в недостающем наблюдении:

> Без устойчивой semantic identity или независимого outcome evidence нельзя
> различить повтор после потерянного ACK и второй намеренно одинаковый заказ.

Epoch доказывает время выдачи идентификатора, но не новизну намерения. Новый
журнал не доказывает полноту прошлого. Capability, не атомарная с эффектом, не
устраняет apply-then-timeout. Escrow сохраняет payload, но не различает две
одинаковые записи.

## Проверка заранее зафиксированных сценариев

| Hidden scenario | Результат |
|---|---|
| H1 apply-then-timeout | Убил D1/D2/D3; D4 не исполняет, но дублирует intent records |
| H2 потеря второго coordinator | D3 оставляет stranded claim; D4 не решает keyless replay |
| H3 returned node с higher epoch | Требует внешнего monotonic CAS; D3 не содержит format/epoch fence |
| H4 post-snapshot v2 order | Snapshot rollback отвергнут всеми; безопасен только при доказанном durable intake |
| H5 partial adapter install | Кандидаты без отдельного version fence не закрывают C3 |
| H6 два recovery controller | CAS/claim сериализуют authority, но не semantic identity одного намерения |
| H7 stale status replica | Остался явной trust boundary; status нельзя считать доказательством outcome |
| H8 permanent partition | Честный исход для старых ambiguous orders — BLOCK |

Проверки были логическими fault scenarios, а не исполнимой симуляцией. Поэтому
они подтверждают veto внутри заданной модели, но не являются production test.

## Контроли

### Single agent

Один агент сразу вернул `NO_SOLUTION` без дополнительного допущения о
существовавшем до ACK независимом журнале и стабильном `order_id`. Это совпало
со строгим итогом полного РАЗЛОМ-4.

### Best-of-4

Контроль выбрал исходную forward-карточку A. Её собственное условие «при
недоказуемой полноте не исполнять» на данном контракте схлопывает forward в
BLOCK и не доказывает C6.

## Исследовательский вывод

- РАЗЛОМ-4 успешно предотвратил четыре привлекательных, но небезопасных
  решения и локализовал общий информационный разрыв.
- В этом case он не превзошёл сильный single-agent по финальному verdict.
- Он дал более богатую причинную трассу: четыре независимых попытки обойти
  невозможность и конкретный counterexample для каждой.
- Best-of-4 оказался слабее: выбрал условный механизм вместо явного
  failure certificate.

Этот результат подтверждает ценность РАЗЛОМ-4 как дисциплины hostile-аудита,
но не подтверждает, что 12 вызовов улучшают exact outcome относительно одного
сильного агента.

## Следующая задача

Следующий pilot должен содержать реально существующую, но неочевидную валидную
мутацию. Иначе сильный Скептик или single-agent может сразу выдать сертификат
невозможности, и специфический эффект четырёх ролей останется неизмеримым.
